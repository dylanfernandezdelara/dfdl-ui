# Decisions

Every value Dylan approved, with the alternatives it was chosen against and one line of why. Append in the same commit as the change. The `dfdl-ui` skill is written from this file, so an entry here is the source; the skill restates it.

Format: `date · area · decision · chosen against · why · status`

Status is `approved`, `interim` (in use but not yet reviewed in its own lab), or `superseded` (with a pointer to the newer entry).

A component page ships at zero strict offenders | eyeballing against the overlay | Dylan: slight misalignments ruin an otherwise crafted layout, and they compound: one 2px error in a section header shifted every element below it on the type lab. | 2026-09-24 | Inline runs and the line box | Inline elements inside text blocks (`em`, `i`, `strong`, `b`, `code`, `kbd`, `sup`, `sub`) get `line-height: 1`, and `sup`/`sub` are positioned rather than shifted, so a serif emphasis or a padded code span cannot inflate a line from 24px to 25px | leave browser defaults | Found by the grid probe: one `<em class="font-display">` in a paragraph pushed the rest of the article a pixel off the grid | approved |

| 2026-09-24 | Motion curves | Enter and exit `cubic-bezier(0.23, 1, 0.32, 1)`; on-screen movement (tabs, reorder) `cubic-bezier(0.77, 0, 0.175, 1)`; drawers `cubic-bezier(0.32, 0.72, 0, 1)`; a spring `linear()` (Emil’s Apple-style config with bounce lowered from 0.2 to 0.15) reserved for gesture-driven motion only. Never `ease-in`, never built-in `ease` on deliberate motion | B: Fork’s built-in `ease`; C: Material decelerate `(0, 0, 0.2, 1)` | Dylan accepted the recommendation in Lab 3 after synchronized ¼-speed comparison. Strong ease-out puts the distance in the first third so the element is where it is going by the time the eye lands; `ease` reads as lag. gooey and beautifului measure near-identical strong ease-outs; kitze uses Tailwind's milder curves and jakub the `ease-out` keyword | approved |
| 2026-09-24 | Durations by frequency | instant 100ms (tooltips, things seen tens of times a day), fast 150 (hover, press, switches), normal 200 (menus, popovers, toasts), slow 300 (dialogs and backdrops), slower 500 (drawers). Nothing UI over 500ms. Keyboard-triggered and 100+/day actions do not animate at all | one duration for everything | Emil’s frequency table; the audit measured 78–150ms hover, 150 menus, 200 dialogs, 300 drawers on the reference sites | approved |
| 2026-09-24 | Exits | Exits run at 75% of the enter duration along the same path (menu closes into its trigger, toast leaves the way it came). Toasts and reduced-motion exits fade only | A: symmetric; C: 50% fade-only for everything | Accepted recommendation. The user has already decided when something leaves; the audit found no reference site shortens its exits; the 25% comes from Emil's and Jakub's published recommendation | approved |
| 2026-09-24 | Press | `scale(0.97)` at 150ms on every pressable; `:active` only, no hover gating needed. Dropped under `prefers-reduced-motion`; color still changes | B: none; C: 0.94 | Accepted recommendation. Smallest scale that still registers as feedback; 0.94 is visible on icon buttons | approved |
| 2026-09-24 | Motion mechanics | Popovers, menus and tooltips scale from `0.95` (tooltips `0.97`) at the trigger’s transform-origin; dialogs from `0.96` at center; drawers translate by their own height; toasts translate 16px (a narrowing of Emil’s recipe, which slides the full height at 400ms). Only `transform`/`translate`/`scale` and `opacity` animate; tab indicators move with `translate`, never `left`/`width`. Transitions, not keyframes, for anything a user can fire twice. Enters start in `@starting-style`, exits in the closed state, `display` flips with `allow-discrete`, so enter and exit can differ. Reduced motion keeps opacity and color and drops movement and scale | JS-driven animations; `transition: all` | Emil’s rules, verified by `getAnimations()` on every lab specimen | approved |

## Architecture

| Date | Area | Decision | Chosen against | Why | Status |
| --- | --- | --- | --- | --- | --- |
| 2026-09-15 | Primitives | Base UI + Tailwind v4 | Radix, plain CSS | Where shadcn and Kitze moved; Fork already uses it | approved |

| 2026-09-15 | Agent guidance | One `dfdl-ui` skill that hands off to Emil, Jakub and Figma skills by name | Google `DESIGN.md`, copying reference skills | Skills are the spec with a validator and measured effect; a values file alone moved nothing in any published test | approved |
| 2026-09-15 | Enforcement | `@shadcn/lint`: no raw colors, no arbitrary values, per-component contracts | prose rules only | Mechanical rules belong in a linter; agents reach zero violations in one round in shadcn's evals | approved |
| 2026-09-15 | Figma to code mapping | `dfdl/X` component naming plus variable code syntax plus descriptions, in place of Code Connect | Organization plan for Code Connect | Code Connect is Organization-only; the convention is what `get_design_context` reads below Code Connect anyway | approved |
| 2026-09-15 | Repo shape | Single Next.js app: docs site, component source, registry build | monorepo | Kitze and AI Elements shape; split later only for an npm or non-web target | approved |
