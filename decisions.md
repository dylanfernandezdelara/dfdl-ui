# Decisions

Every value Dylan approved, with the alternatives it was chosen against and one line of why. Append in the same commit as the change. The `dfdl-ui` skill is written from this file, so an entry here is the source; the skill restates it.

Format: `date · area · decision · chosen against · why · status`

Status is `approved`, `interim` (in use but not yet reviewed in its own lab), or `superseded` (with a pointer to the newer entry).

| 2026-09-24 | Accent set | Two approved accents, chosen once per product with `data-accent` on the root: **ember** (hue 48, default; vividness 0.60 of ceiling light, 0.55 dark) and **indigo** (hue 281, Fork; 0.452 light, 0.80 dark, the value dylanfdl.com already shipped). Dark vividness is set per accent because blue’s sRGB chroma ceiling halves between L 52% and L 72% and one factor cannot serve every hue | one accent for every product; deriving dark from light with one factor | Dylan wants Fork to stay blue while other apps use ember. Identity lives in the neutral, type, rhythm, radius, elevation and motion; the accent is the one dial a product turns. Radix Themes uses the same model. Ember vividness raised from 0.452 to 0.60 after the 1b boards: at 0.452 the send button sat too close to the neutrals to read as an action | approved |

| 2026-09-24 | Type scale | Weight-led: body, heading and title share 15px/24px; hierarchy from weight 550, family and color. Display 32/40 at 400, tracking -0.01em. | 2026-09-24 | Serif scope | Lora on every heading level and the display, including section headers inside app panels. | 2026-09-24 | Radius | Round: xs 8 · sm 10 · md 12 · lg 16 · xl 24 · full. Concentric nesting is the rule: outer = inner + padding. Controls at sm, fields at md, cards at lg, sheets at xl | A: previous 4/6/8/12/16; B: soft 6/8/10/14/20 | Dylan’s pick (`?r=c`). Fork’s existing 0.625rem family, so Fork needs no radius change; closest to ChatGPT and Linear | approved |
| 2026-09-24 | Type roles as tokens | Type is set only through role utilities `text-display`, `text-title`, `text-heading`, `text-body`, `text-ui`, `text-caption`, each carrying size, leading and weight; families via `font-display` and `font-heading`. Ad hoc `text-sm leading-6` combinations are not allowed | per-property Tailwind classes | One place to change a role; the linter and `cn` know the vocabulary; Figma text styles map one to one | approved |
| 2026-09-24 | Quiet mode | `<html data-quiet>` for data-dense products: headings and display go system sans, the accent roles collapse into the neutrals (selection carried by weight and hairlines, focus ring is `fg-strong`). Neutrals, type roles and sizes, radius, elevation and motion are unchanged. trackcongress runs in quiet mode | apply Lora headings and ember everywhere; or exempt trackcongress from dfdl entirely | Phase 5 trackcongress before/after. Serif headlines on a stacked feed read as two registers per row, and a fifth color on a page where green, red, amber and party colors already carry meaning asks the reader to learn what orange means. Tool surfaces are quieter than reading surfaces at Radix, Vercel and Linear too. Warm charcoal dark and the 15px heading role stand in quiet mode | approved |
| 2026-09-15 | Grid | 8px minor, 24px major rhythm with overlay | none considered | Already proven on dylanfdl.com; overlay ported as is | approved |
| 2026-09-24 | Grid alignment, enforced | Every block's top edge and every control's height land on the 8px grid; the 4px half-step is allowed only for centering a 24px line in a 48px row and for padding inside a control; nothing fractional. Line-heights are fixed pixel multiples of 4, never unitless. A 1px border that would push content off the grid becomes a `hairline`, `hairline-t` or `hairline-b` shadow (no layout space). Verification is mechanical: `Shift+G` in the browser outlines every offender with its reason; `scripts/probes/grid.js` returns the same list for agents. A component page ships at zero strict offenders | eyeballing against the overlay | Dylan: slight misalignments ruin an otherwise crafted layout, and they compound: one 2px error in a section header shifted every element below it on the type lab. Measured, not judged | approved |
| 2026-09-24 | Inline runs and the line box | Inline elements inside text blocks (`em`, `code`, `kbd`, `sup`, `a`, `span`) get `line-height: 1`, and `sup`/`sub` are positioned rather than shifted, so a serif emphasis or a padded code span cannot inflate a line from 24px to 25px | leave browser defaults | Found by the grid probe: one `<em class="font-display">` in a paragraph pushed the rest of the article a pixel off the grid | approved |
| 2026-09-15 | Type families | System sans body, Lora display and emphasis, Geist Mono code and metadata | Geist everywhere, Inter + serif | Continuity with dylanfdl.com; zero font cost for body | approved |
| 2026-09-15 | Motion, interim | `cubic-bezier(0.23, 1, 0.32, 1)`, 150ms hover, `scale(0.97)` press | none yet | Emil's defaults so labs 1 and 2 do not feel broken before the motion lab | superseded by 2026-09-24 motion |
| 2026-09-24 | Motion curves | Enter and exit `cubic-bezier(0.23, 1, 0.32, 1)`; on-screen movement (tabs, reorder) `cubic-bezier(0.77, 0, 0.175, 1)`; drawers `cubic-bezier(0.32, 0.72, 0, 1)`; a spring `linear()` (Apple-style, bounce 0.15) reserved for gesture-driven motion only. Never `ease-in`, never built-in `ease` on deliberate motion | B: Fork’s built-in `ease`; C: Material decelerate `(0, 0, 0.2, 1)` | Dylan accepted the recommendation in Lab 3 after synchronized ¼-speed comparison. Strong ease-out puts the distance in the first third so the element is where it is going by the time the eye lands; `ease` reads as lag. Every audited site converges here | approved |
| 2026-09-24 | Durations by frequency | instant 100ms (tooltips, things seen tens of times a day), fast 150 (hover, press, switches), normal 200 (menus, popovers, toasts), slow 300 (dialogs and backdrops), slower 500 (drawers). Nothing UI over 500ms. Keyboard-triggered and 100+/day actions do not animate at all | one duration for everything | Emil’s frequency table; the audit measured 78–150ms hover, 150 menus, 200 dialogs, 300 drawers on the reference sites | approved |
| 2026-09-24 | Exits | Exits run at 75% of the enter duration along the same path (menu closes into its trigger, toast leaves the way it came). Toasts and reduced-motion exits fade only | A: symmetric; C: 50% fade-only for everything | Accepted recommendation. The user has already decided when something leaves; the audit found reference sites run exits about a quarter shorter | approved |
| 2026-09-24 | Press | `scale(0.97)` at 150ms on every pressable; `:active` only, no hover gating needed. Dropped under `prefers-reduced-motion`; color still changes | B: none; C: 0.94 | Accepted recommendation. Smallest scale that still registers as feedback; 0.94 is visible on icon buttons | approved |
| 2026-09-24 | Motion mechanics | Popovers, menus and tooltips scale from `0.95` (tooltips `0.97`) at the trigger’s transform-origin; dialogs from `0.96` at center; drawers translate by their own height; toasts translate 16px. Only `transform`/`translate`/`scale` and `opacity` animate; tab indicators move with `translate`, never `left`/`width`. Transitions, not keyframes, for anything a user can fire twice. Enters start in `@starting-style`, exits in the closed state, `display` flips with `allow-discrete`, so enter and exit can differ. Reduced motion keeps opacity and color and drops movement and scale | JS-driven animations; `transition: all` | Emil’s rules, verified by `getAnimations()` on every lab specimen | approved |
